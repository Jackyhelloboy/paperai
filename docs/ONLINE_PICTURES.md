# Online worksheet pictures

The scanning Worker, same-origin Pages gateway, browser preview, and editable Word package now share a picture retrieval path. The existing twenty fruit SVG/PNG assets are preserved, but written picture requests no longer use hand-drawn SVG substitutes.

1. The browser identifies explicit, known object requests such as `duck pic` or `mango picture`. Common Hindi and Telugu object names are mapped to search subjects. It never searches using the whole question paper.
2. `GET /api/pictures/search?q=duck` searches Wikimedia Commons file metadata, ranks title matches and simple illustration descriptions, and returns up to eight candidates. It accepts only images individually marked Public domain or CC0, with no attribution or other restrictions. A metadata CC0 notice does not qualify an image.
3. `GET /api/pictures/asset?title=File:...` rechecks the file's current license and requests a raster thumbnail up to 960 pixels. It only fetches metadata from Commons and pixels from the `/wikipedia/commons/` paths on `upload.wikimedia.org` or `thumb.wikimedia.org`; caller-supplied URLs and redirects are rejected. Metadata URL tracking parameters are removed. Byte limits and image signatures are checked.
4. The browser preserves the image's aspect ratio, converts it to PNG, and stores the pixels in the paper's media collection. The Word export embeds those PNG bytes; it contains no external-image relationships. Source, creator and license are preserved in picture alternative text, and the source link is visible in the picker.

Automatic insertion requires an explicit supported placeholder and a complete subject match in the candidate title. This is conservative metadata matching, not visual verification. Missing results preserve the written request with a review note. Existing scanned drawings are not automatically replaced. Teachers can use **Find pictures**, inspect the results, and choose a question line or an existing picture to replace. Labels and response boxes already attached to a replaced picture remain in place. Replacing a native Office/PDF image invalidates the original-package shortcut, so the new pixels reach the Word download.

The search uses the public MediaWiki API; it needs no new paid model, API key, or GPU. The shared `frontend/vendor/commons-pictures.js` module runs both in the Worker and in the browser. If the server cannot reach Commons, the browser retries the public API directly with `origin=*` and without credentials, using the same license, host, relevance, size and signature checks. Previews use only the validated Wikimedia thumbnail URL. This avoids making free public-image retrieval depend on the backend's network access; the paper itself is never sent to Commons. Retrieval can still fail or return unsuitable results, so teachers should review the choice. General searches use the supplied language; the built-in common object aliases help Hindi/Telugu requests. Wikimedia Commons is not a child-content certification service. Filename/description exclusions reduce obvious unsuitable results but do not replace human review.

Validation: `node tests/picture-search.cjs`, `node tests/default-picture-materialization.cjs`, `node tests/public-gateway.cjs`, and the existing Word/layout regressions. `.github/scripts/check-pictures.cjs` performs two bounded live searches and image downloads when run in an environment that can reach the deployed API; results must be reported separately from mocked tests.


## Required rules for the Internet Picture Agent

These rules apply to future automatic selection, teacher-assisted selection, preview, and editable Word export. They describe **requirements**, not a claim that every verification agent is implemented today.

1. **Source-first, never invent evidence.** Preserve every existing illustration from a scanned paper or uploaded document unless the teacher explicitly replaces it. An OCR crop or original embedded image is evidence; a retrieved stock picture is not evidence and must never silently replace it.
2. **Only search for identified objects.** Detect explicit prompts such as "duck pic" and teacher-selected objects. Parse each picture request separately, including supported Hindi and Telugu names. Never transmit the complete paper, student data, or private document text to public image search providers.
3. **Retrieval before drawing.** For new object pictures, prefer licensed, clear raster images retrieved online to approximate SVG shapes generated from code. Do not insert fabricated SVG approximations just to fill a missing result. Keep original source SVGs where they actually belong to the source document; geometry such as tables, arrows, and answer lines can still use native document shapes.
4. **Use authorized images only.** Only use sources whose per-file license and use rights pass validation. Current automated retrieval permits public-domain and CC0 Wikimedia Commons images. Keep creator, source link, and license metadata; never infer licensing merely from a search-engine thumbnail or a search-results page.
5. **Verify the visual content, not only the filename.** A title/description match is only a candidate. Before claiming an image was visually verified, run actual image-content inspection (for example a trusted vision model) for the requested object and scene. Check that the main object is recognizable to a young child, complete, uncropped, uncluttered, not misleading, not frightening or inappropriate, and free of watermarks, unrelated text, and duplicate embedded labels. If visual verification is unavailable, mark the result as metadata-matched only; do not report it as vision-verified.
6. **Confidence and ambiguity.** Auto-insert only if the explicit request, license, image signature, relevance, and configured visual-verification threshold all pass. Multiple subjects, ambiguous names, uncertain licensing, unclear/partial objects, visual-model failure, or disagreement require teacher selection. Do not hallucinate that a picture was found or insert a plausible but unverified substitute.
7. **Child-friendly worksheet style.** Choose clear, high-contrast, reasonably detailed real-world photos or illustrations suitable for the requested age and learning task. Prefer clean outline/raster pictures for black-and-white printable worksheets, and full-color photos when color is educationally important. Use white or simple backgrounds, consistent visual scale, and enough resolution at print size.
8. **Image bytes, not page screenshots.** Download a permitted high-resolution raster asset instead of screenshotting a website, unless the specific educational artifact requires a screenshot and its use is permitted. Validate declared MIME against magic bytes, bound dimensions and total bytes, reject redirects and unknown hosts, and convert accepted images to a supported Word-compatible image format.
9. **Correct question placement.** Attach each image to the correct question, row, and intended answer region, not the next arbitrary paragraph. For grouped pictures, preserve source order and intended count. Never solve the exercise or add answers, labels, or clues absent from the source.
10. **Editable Word export.** Embed actual image pixels locally inside DOCX (no remote URLs), retain aspect ratio, visible content, predictable alignment, margins, spacing and print resolution. Pictures must remain independently selectable/replaceable Word objects; text, tables, question numbers, and answer boxes remain editable.
11. **Review, provenance, and recovery.** Display candidate previews and source/license details; offer teacher replace/approve controls, retain user choices, and make failures visible. When no valid image is available, keep an explicit placeholder/review note rather than silently creating an SVG or choosing an unrelated image. Preserve the original image on failed replacement.
12. **Verification and release gate.** Test object parsing, Unicode aliases, licensing, unsafe/unrelated results, URL restrictions, signature and size checks, offline/provider failure, insertion position, aspect ratio, native DOCX image presence, and original-image preservation. Add a fixture covering wrong-image rejection. Run focused automated tests and a real end-to-end document export before reporting a feature as deployed. Mocked tests alone do not demonstrate live internet or vision behavior.

### Implementation status boundary

The existing Commons metadata search, image download, preview picker, PNG conversion, and Word embedding are already documented above. **Automated visual verification of candidates is not established by the current metadata matching**. A future vision-verification stage must be implemented and tested before describing this pipeline as fully automatic or vision-verified. New code must preserve the original-paper transcription invariants in `ARCHITECTURE.md` and avoid exposing credentials to browser code.


## Image-only screenshot capture for Word

The browser takes a clean PNG raster capture of the selected, licensed image pixels on its own canvas before export. This is an **image screenshot**, not a screenshot of a search page or browser window. The capture retains proportions, uses a white background and high-quality resampling, and is stored as an embedded PNG image object in Word. No remote image URL is needed to open the DOCX. The screenshot does not create new image rights: Commons public-domain/CC0 checks still apply before capture.

This screenshot path is implemented by `prepareQuestionPicture` in `frontend/index.html`, which exports `captureMethod: 'image-pixels-screenshot'`. Search still retrieves the source picture pixels first; there is no way to screenshot an online image without first receiving its pixels. Screenshot capture does not verify that the selected object is semantically correct. Teacher review is still required for uncertain choices and source scans are never silently replaced.


## Reference worksheet image style (October 2026)

The requested visual style matches the supplied reference ZIP: bold, recognizable black-and-white outlines, clean white backgrounds and straightforward school worksheet clipart (for example duck, camel, classroom and book). A search for an object such as `apple` first uses the phrase `apple black and white outline clipart`, then `apple black and white line drawing`, then `apple outline coloring page`. Such style-matched Commons results are ranked higher than generic photos or scene illustrations. Search candidates still require public-domain/CC0 verification and the existing unambiguous subject safeguards. Results without a reliable single-object title remain for teacher review. The PNG screenshot is made from the licensed image pixels before the editable Word export; do not screenshot the search webpage itself.

The ZIP is a visual reference, **not** an authorization to redistribute its files; do not commit those images or infer their licenses without provenance.


## OCR → Gemini evidence review → specific picture request → Word

1. OCR must extract source page text and original images before interpreting picture requests. The source PDF/image remains authoritative. The existing Gemini OCR/verification route may correct a doubtful OCR token **only if its visual evidence supports that correction**; never rewrite wording by dictionary guess or semantic plausibility, invent missing text, or solve worksheet questions. Uncertain readings require review.
2. Detect only an explicit object-picture instruction (examples: `apple pic`, `Add picture of apple`, `Draw a duck`, `Paste mango picture`). Parse the single supported object name from that instruction, not a full sentence, full page or entire PDF. Unsupported/ambiguous requests stay reviewable and are not searched automatically.
3. Before making a new picture request, honor any real original embedded PDF image/figure associated with the question. Such a source picture is never automatically replaced merely because it is line art or SVG.
4. For an explicit missing image, search Commons for `<object> black and white outline clipart`, then other worksheet-style outline phrases. Apply current per-file license, exact-subject relevance, and suitability constraints. Filename confidence is not vision verification; uncertain matches remain a teacher choice.
5. For the selected permitted image, capture its **image pixels only** to a white-background PNG canvas, embed the PNG at the corresponding question/row in editable Word, retain source/license information and the surrounding text/answer positions. If search fails, leave the request and a visible review note; do not synthesize an approximate SVG.
6. Tests must cover spelling/figure evidence preservation, object-only search queries, existing source-image priority, partial row failures, and actual DOCX media plus placement. The presence of code/tests is not proof of a successful end-to-end verification run.
