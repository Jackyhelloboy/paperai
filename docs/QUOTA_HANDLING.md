# Free AI quota and scan recovery

The 11 October 2026 screenshot showed 1,990.63 reported neurons remaining and a daily-limit scan failure. The live Worker independently reported a stored daily provider rejection. The dashboard had been reading only a periodically deployed analytics snapshot, so its remaining figure did not reflect the rejection.

The frontend now reads both account-wide Cloudflare analytics and `/api/usage`. Analytics remain explicitly reported totals; they are not presented as an enforcement balance. A confirmed Workers AI daily rejection shows **Free AI limit reached** and **Free AI available: 0**, even while analytics report a lower usage total. The quota bar now displays a full confirmed-pause state labelled **Free AI paused until reset**, rather than a misleading partial percentage during a live rejection. When unblocked, reported percentage and remaining are calculated together from the current analytics total and daily reference. The explanatory text remains visible on small screens. Missing or previous-day analytics show a dash rather than a fabricated balance.

The Worker records provider rejection separately from its approximate token-based usage totals. It does not invent a 10,000-neuron charge for a failed request, and a token estimate alone cannot block scanning. Confirmed rejection prevents further AI calls for that UTC day; a tracker outage does not cause a false block. The response includes `reset_at`, `server_time` and `Retry-After`. The frontend also remembers an actual rejection through a reload or status outage and expires it at the next UTC day. Cloudflare's reset is midnight UTC, or 5:30 AM India time.

Daily error code `3036` is distinct from temporary capacity error `3040` and ordinary rate-limit responses. Busy responses allow a later retry and do not exhaust the dashboard. An application error returned through the Pages proxy is not submitted again to the direct Worker URL. Provider exhaustion is never automatically retried and there is no paid-model fallback.

If a verification pass hits the daily limit, the usable primary OCR result is retained and the provider block is published. PDF resume continues to keep completed pages and source pictures while the same file remains open. Failed scans clear the progress indicator, restore the same document’s existing editable result, and leave controls usable. Word, spreadsheet and embedded-text extraction, optional corrections and Word export remain available without AI.

Run `node tests/ai-quota.cjs`, `node tests/scan-resume.cjs` and `node tests/automatic-upload.cjs`. The quota suite exercises the actual Worker handler and Durable Object with mocked provider responses, the actual frontend request and dashboard functions, UTC rollover, outages, first-pass retention, no duplicate submissions, and progress/result restoration. The deployment workflow runs all eleven document/quota/upload regression suites. Worker deployment also runs quota checks before publishing.

This fixes quota reporting and handling; it cannot increase Cloudflare's shared free allocation. A successful post-reset real handwriting scan is a separate check and must not be claimed while the provider is still blocking AI requests. The existing free-only configuration is retained.
